## Browser test setup

Install browser binaries with `npx playwright install chromium` inside `invora-web`. Start an isolated Development stack with a fresh database and matching browser origin. Create a private JSON file containing its bootstrap key:

```json
{"Auth__BootstrapKey":"your-isolated-test-bootstrap-key"}
```

Set `INVORA_E2E_ENV` to that private file and optionally `INVORA_WEB_URL` to the stack's origin, then run `npm run e2e`. The suite creates/reuses a synthetic test owner and posts synthetic inventory/sales/purchases. **Use a dedicated test database**, never your real store database. The suite intentionally leaves its posted fixtures for inspection. Screenshots/traces are under ignored `artifacts/`.

For commercial activation acceptance, enable `Licensing__Required=true` and the matching public verification key on the isolated API. Set `INVORA_LICENSE_E2E=1` and `INVORA_LICENSE_E2E_KEY` to the private test signing-key path, then run only `commercial-license.spec.ts`. This test expects a shop without an active licence, checks write denial and performs a real browser activation. Other counter workflows run with licensing disabled or an already activated test shop. Never include a private signing key in browser assets or customer releases.

Container acceptance has also been run with `invora_runtime`, proving that migrations/owner privileges are unnecessary for normal browser transactions. Encrypted backup/restore and the supplied reconciliation SQL were rehearsed against an isolated restored database.
